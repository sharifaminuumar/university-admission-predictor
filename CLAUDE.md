# CLAUDE.md

Project memory for the Ghanaian University Admission Predictor. Keep this file current — see **Maintenance** at the bottom.

## Project Overview

A Flask web app that predicts which Ghanaian university programs a student qualifies for from their WASSCE results. A student picks a target institution and enters core + elective grades; the app computes their Best-6 aggregate and checks it against each program's cutoff and subject-specific requirements.

Universities currently seeded: **UG**, **KNUST**, **UDS**, **UPSA**.

## Core Commands

```bash
# Run the dev server (http://127.0.0.1:5000)
python run.py

# Reseed the database from data/*.json (drops and recreates all tables)
python seed_db.py
```

**Tests:** there is no test suite yet. `requirements.txt` has no test runner installed. When tests are added, prefer `pytest` and document the run command here.

## Architecture & Layout

```
run.py                  entrypoint; app = create_app(); app.run(debug=True)
seed_db.py               loads data/*.json into the DB via the app factory
app/
  __init__.py             app factory (create_app); configures instance-relative SQLite URI
  models.py               SQLAlchemy ORM: University, Program
  routes.py                Flask Blueprint ("main"): / (index) and /api/predict (POST)
  eligibility_engine.py    pure functions, no Flask/DB imports — the actual prediction logic
  templates/index.html     single-page form UI (Tailwind CDN)
  static/main.js           builds grade dropdowns/elective rows, POSTs to /api/predict, renders results
  static/style.css
data/*.json               one file per university: programs + cutoff_aggregate + requirements
instance/admissions.db     canonical SQLite file (gitignored, regenerated by seed_db.py)
```

**Data flow:** `main.js` POSTs the raw form payload to `/api/predict` → `routes.py` builds a `student_grades` dict and a flattened `student_subjects` portfolio via `build_subject_portfolio()` → for each `Program` row belonging to the selected university, `evaluate_eligibility()` checks mandatory subjects/grades, then (if eligible) `calculate_aggregate()` computes that program's Best-6 aggregate → programs where `aggregate <= cutoff_aggregate` are returned as JSON.

**`eligibility_engine.py`** is the algorithmic core, deliberately decoupled from Flask and the DB so it stays independently testable:
- `build_subject_portfolio(student_grades)` — flattens the raw "Elective N / Elective N Grade" form keys into a single `{subject_name: grade}` map.
- `evaluate_eligibility(student_grades, program_data)` — validates mandatory cores/electives and minimum grades; returns `(is_eligible, reason)`.
- `calculate_aggregate(student_subjects, program_data)` — computes the Best-6 aggregate. **Important:** the 3rd core subject depends on the program's `requirements.elective_category_pool` — `"Sciences"` always uses Integrated Science, anything else (`"Any"`, etc.) uses `min(Integrated Science, Social Studies)`. This must be computed **per program**, not once globally, since different programs in the same request can have different pools.

**Models (`app/models.py`):**
- `University` — `name`, `short_code` (e.g. `"UG"`, `"KNUST"`) — matched against the frontend's `university_code` value.
- `Program` — belongs to a `University`; `cutoff_aggregate` (int); `requirements` is a Python dict transparently (de)serialized to/from a JSON text column (`_requirements`). This lets each program have arbitrary requirement shapes (`mandatory_cores`, `mandatory_electives`, `elective_category_pool`) without schema migrations.

**Database path:** the canonical SQLite file is **`instance/admissions.db`**, resolved via Flask's `instance_relative_config=True` + `app.instance_path` in `create_app()` (`app/__init__.py`) — this makes the path stable regardless of the working directory the app is launched from. Never hardcode a different `sqlite:///...` path. A stray root-level `admissions.db` should not exist; if one appears, it's safe to delete (it's gitignored and fully regenerable via `python seed_db.py`).

## Developer Rules

- **Encoding:** all text files (`.py`, `.md`, `.json`, `.txt`, `.gitignore`, etc.) must be UTF-8. This repo previously had `.gitignore`/`README.md`/`requirements.txt` corrupted as UTF-16, which silently broke `.gitignore` pattern matching — verify with `file <path>` if anything seems off.
- **Never track compiled/generated artifacts:** no `*.pyc`, `__pycache__/`, or `*.db`/`*.sqlite3` files in git. `.gitignore` already excludes these; don't force-add over it.
- **Git commits are manual only.** Claude must never run `git commit` or `git push`. Always propose the exact `git add`/`git commit -m "..."` commands and let the user run them.
- When adding a new university, follow the runbook (data JSON → `seed_db.py` block → `index.html` dropdown option → `main.js` `displayResults` label).
